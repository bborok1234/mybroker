# MyBroker Surfaces

MyBroker has four separate surfaces. They must not collapse into one dashboard.

## 1. Flyhigh Operator Dashboard

Purpose: project implementation progress.

Shows issues, pull requests, direction reviews, merge gates, blockers, validation, live repo state, and next actions. It may link to MyBroker artifacts, but it must not render product market maps or user action candidates inline.

## 2. MyBroker Ops/Artifact Dashboard

Purpose: artifact trust and local run inspection.

Shows report counts, source coverage, freshness, validation, generated artifact paths, data quality, and blockers. It is for builders/operators, not beginner users.

Must not be treated as the product UX.

For the autonomous daily research loop it may show topic coverage, latest run status, source freshness, collection gaps, topic memory health, and artifact paths. It still must not render the beginner market map or action candidates as the main product surface.

## 3. MyBroker Product Surfaces

Purpose: beginner-facing market understanding.

Generated by `mybroker brief`, `mybroker appliance today`, `mybroker appliance agenda`, `mybroker appliance readiness`, `mybroker appliance journal`, `mybroker appliance tasks`, and `mybroker appliance task-ledger`, these are the beginner-facing user surfaces. They show market/narrative maps, key themes, three scenario paths, persona viewpoints, beginner explanations, next inspection questions, daily reading order, source fan-out, freshness/readiness status, role-specific analyst notes, queued analyst work, task status history, and research-only action candidates.

Must not show adapter IDs, schema names, raw validation logs, Flyhigh gates, or implementation details.

`reports/product/journal.html` is not a project dashboard. It is the daily analyst work log: what changed, what stayed stable, what each analyst role noticed, what evidence is weak, and which questions should continue tomorrow.

`reports/product/daily-agenda.html` is not an ops dashboard. It is the phone-first daily study order: what to read first, which sources influenced the top topic, which evidence is weak or stale, what each analyst role should check next, and which beginner-readable questions should continue the loop.

`reports/product/readiness.html` is not the Flyhigh project dashboard. It is the personal analyst's phone-first trust check: whether today's daily surfaces and required machine artifacts are fresh enough, which files are stale or missing, what scheduler status is known, and what local run command should be used next.

`reports/product/tasks.html` is not an executor. It is the role-based task board for the next local research loop. Queued tasks do not run live network, host writes, notification send, credential access, account access, trading, or discretionary advice.

`reports/product/task-ledger.html` is not a project tracker. It is the personal analyst's local work memory: new, carried, blocked, and retired task states across daily runs.

## 4. Machine Artifacts

Purpose: reproducibility and audit.

Machine-readable artifacts include:

- `public_evidence_catalog.v1`
- `topic_config.v1`
- `daily_research_plan.v1`
- `topic_memory.v1`
- `daily_brief_agenda.v1`
- `daily_readiness.v1`
- `personal_analyst_journal.v1`
- `personal_analyst_task_queue.v1`
- `personal_analyst_task_ledger.v1`
- `scenario_report.v1`
- `market_verdict.v1`
- `research_report.v1`

These are inputs for validators, dashboards, product briefs, and Flyhigh evidence. They are not user-facing screens.
